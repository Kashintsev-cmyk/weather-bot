# test

Учебный (тестовый) проект: телеграм-бот, который собирает погоду и состояние моря
для Адлера (Сочи) сразу с нескольких площадок и выдаёт обобщённую подробную сводку.

## Что делает бот

- Опрашивает площадки параллельно: **Open-Meteo**, **OpenWeatherMap**, **wttr.in** — по погоде,
  **Open-Meteo Marine API** — по морю (температура воды, волна, период, зыбь),
  **USGS** — по землетрясениям рядом с точкой.
- Приводит ответы к единым моделям (`app/models.py`): скорости — в км/ч, описания — в русский,
  время — к часовому поясу точки прогноза, рассвет/закат — к виду `06:15`.
- Считает обобщение по площадкам: медиана каждого поля, разброс (min…max), мода описаний,
  круговое среднее для направлений ветра и волны, а также почасовой консенсус на 48 часов
  (трёхчасовые записи OpenWeatherMap и wttr.in приводятся к мм/ч, поэтому медианы сопоставимы).
- Определяет опасные события (`app/events.py`): дождь, ливень, гроза, град, шквал, ураганный
  ветер, риск смерчей, туман, жара, заморозки, резкое похолодание, сильное волнение, шторм
  на море, свежие землетрясения и возможный риск цунами.
- Выдаёт подробный текст: сейчас, события, прогноз по дням (осадки, вероятность, ветер, порывы,
  УФ, рассвет/закат), состояние моря, разбор по площадкам и примечания о расхождениях.
- Присылает **ежедневную сводку в 07:30 (МСК)** и **оповещения за 60 минут до начала события**.
- Кэширует сводку (по умолчанию 5 минут), чтобы не дёргать площадки на каждое сообщение.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/start` | приветствие и инлайн-кнопки |
| `/weather` | погода сейчас и прогноз по дням |
| `/sea` | море: вода, волна, зыбь и прогноз волнения |
| `/events` | что опасного ждёт в ближайшие часы |
| `/full` | полная сводка с событиями, разбором площадок и расхождений |
| `/subscribe` | подписка на утреннюю сводку и оповещения |
| `/unsubscribe` | отключить рассылку |
| `/status` | состояние рассылки, подписки и файла состояния |
| `/whoami` | показывает `chat_id` (для белого списка) |
| `/help` | справка |

## Рассылка и оповещения

Рассылка живёт внутри процесса бота (`app/notify.py`) и раз в `NOTIFY_POLL_SECONDS` (по умолчанию
60 с) проверяет расписание:

- **Утренняя сводка** уходит один раз в сутки в `NOTIFY_DAILY_TIME` (по умолчанию 07:30 по времени
  точки). Если бот лежал в момент отправки, сводка уйдёт при первом запуске в пределах
  `NOTIFY_DAILY_GRACE_MINUTES` (по умолчанию 180 минут) — догонять её вечером бессмысленно.
- **Оповещения о событиях** уходят за `NOTIFY_EVENT_LEAD_MINUTES` (60 минут) до начала события,
  в пределах `NOTIFY_EVENT_HORIZON_HOURS` (12 часов) вперёд. Ключ события — тип и час начала
  (`rain:2026093008`), поэтому об изменении прогноза в пределах того же часа повторно не напишем,
  а новое событие в следующем часе придёт.
- Подписки и уже отправленное хранятся в JSON-файле `STATE_FILE`
  (по умолчанию `state/bot_state.json`), история чистится через 7 дней. Перезапуск и обновление
  бота не приводят к повторным уведомлениям.
- Подписчики: все, кто вызвал `/subscribe`, плюс `chat_id` из `TELEGRAM_ALLOWED_CHAT_IDS`
  (если файл состояния пустой — белый список становится списком рассылки).
- Пороги событий настраиваются: `NOTIFY_RAIN_MM_PER_HOUR`, `NOTIFY_RAIN_PROBABILITY`,
  `NOTIFY_GUST_KMH`, `NOTIFY_HURRICANE_GUST_KMH`, `NOTIFY_WAVE_M`, `NOTIFY_WAVE_SEVERE_M`,
  `NOTIFY_TEMP_DROP_C`, `NOTIFY_HEAT_C`, `NOTIFY_TORNADO_CAPE`, `TSUNAMI_MAGNITUDE`.
- Выключить всё разом: `NOTIFY_EVENTS_ENABLED=false`.

## Требования

- Python 3.10+
- Токен бота от [@BotFather](https://t.me/BotFather) — для запуска телеграм-части
- Ключ [OpenWeatherMap](https://home.openweathermap.org/api_keys) — опционально:
  без ключа площадка пропускается, сводка продолжает работать на остальных

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # заполните TELEGRAM_BOT_TOKEN и, при желании, OPENWEATHER_API_KEY
```

## Запуск

```bash
python3 run_bot.py                            # бот в режиме long polling + рассылка
python3 run_bot.py --check                    # проверить токен методом getMe и выйти
python3 run_bot.py --events                   # события ближайших часов в консоль (без Telegram)
python3 run_bot.py --notify-dry               # прогон рассылки без отправки: что ушло бы подписчикам
python3 run_bot.py --notify-test              # отправить подписчикам проверочное сообщение

python3 weather_report.py                     # сводка в терминал (телеграм не нужен)
python3 weather_report.py --sea-only          # только море
python3 weather_report.py --out hello.txt     # записать сводку в файл
python3 weather_report.py --json report.json  # плюс машинночитаемый JSON
python3 weather_report.py --sections current,events,forecast --days 1

python3 -m pytest                             # тесты (сеть не используется)
```

## Площадки

| Площадка | Что даёт | Ключ |
| --- | --- | --- |
| Open-Meteo | текущая погода, прогноз по суткам, УФ-индекс, рассвет/закат | не нужен |
| OpenWeatherMap | текущая (`/data/2.5/weather`) и прогноз 3-часовыми шагами (`/data/2.5/forecast`) | нужен |
| wttr.in | текущая погода, 3 суток, вероятность дождя | не нужен |
| Open-Meteo Marine | температура воды, высота и период волны, зыбь | не нужен |
| USGS | землетрясения в радиусе точки (FDSN `query`, GeoJSON) | не нужен |

## Как считается обобщение

- по каждому числовому полю — **медиана** среди площадок; отдельно считаются минимум и максимум,
  из них собирается строка «Разброс по источникам»;
- описание погоды — **самое частое** среди площадок, плюс перечисление, кто что сообщил;
- направления ветра и волны — **круговое среднее** (корректно учитывает переход через 360°);
- если разброс температур ≥ 3 °C, в конце сводки появляется предупреждение;
- упавшая площадка не ломает сводку: её текст ошибки уходит в «Примечания»,
  а остальные площадки продолжают работать.

## Развёртывание под systemd

Проект живёт в `/home/botuser/bots/weather-bot`, юнит — `/etc/systemd/system/weather-bot.service`:

```ini
[Service]
Type=simple
User=botuser
Group=botuser
WorkingDirectory=/home/botuser/bots/weather-bot
EnvironmentFile=/home/botuser/bots/weather-bot/.env
Environment=PYTHONUNBUFFERED=1
Environment=PYTHONPATH=/home/botuser/bots/weather-bot
ExecStart=/home/botuser/bots/weather-bot/venv/bin/python /home/botuser/bots/weather-bot/run_bot.py
Restart=on-failure
RestartSec=10
StandardOutput=append:/home/botuser/bots/weather-bot/logs/bot.log
StandardError=append:/home/botuser/bots/weather-bot/logs/bot.log
```

```bash
sudo systemctl enable --now weather-bot.service   # включить и запустить
systemctl status weather-bot.service             # состояние
tail -f /home/botuser/bots/weather-bot/logs/bot.log   # логи
sudo systemctl restart weather-bot.service       # после обновления кода
```

Рассылка работает внутри процесса бота, поэтому отдельные таймеры не нужны. Проверить рассылку
без Telegram можно командой `./venv/bin/python run_bot.py --notify-dry` (состояние не меняется),
а проверить связь с Telegram — `./venv/bin/python run_bot.py --notify-test`.

Второй экземпляр бота запускать нельзя: Telegram отдаёт обновления только одному получателю
(остальные получают 409 Conflict). Поэтому `main()` берёт блокировку `state/bot.lock`, и вторая
копия сразу завершается с сообщением «Бот уже запущен (pid …)». Остановка по SIGTERM (в том числе
`systemctl stop`) занимает меньше секунды, а `TimeoutStopSec=15` в юните — страховка на случай
зависшего сетевого вызова.

## Соглашения

- Сообщения коммитов — краткие и по существу (например, `Add README`).
- Основная ветка разработки — `main`.
- Секреты живут только в `.env` (файл в `.gitignore`), в коде — только чтение переменных окружения.
- Тексты и docstring — на русском, имена в коде — на английском.

## Ограничения

- Реальный ответ OpenWeatherMap в тестах не снят (ключа нет): фикстуры `openweathermap_*.json`
  синтетические, собраны строго по схеме документации — см. поле `"_note"` внутри файлов.
- wttr.in не отдаёт русские описания даже при `lang=ru`, поэтому они переводятся по числовому
  коду WWO (`app/wwo.py`) с резервным переводом английских фраз.
- Площадки используют разные модели и время наблюдения, поэтому числа расходятся — это нормально
  и показывается в сводке явно.
- Сводка обновляется по запросу и кэшируется на 5 минут; расписание рассылки живёт в том же
  процессе (systemd-юнит `weather-bot.service`), отдельного крона не требуется.
- Оповещения о землетрясениях — это не официальное предупреждение, а напоминание проверить
  сводки USGS/МЧС; риск цунами оценивается грубо (магнитуда и глубина).
- Детектор событий работает по консенсусу площадок: чем больше площадок отвалилось,
  тем меньше уверенность в событиях (медиана считается по тому, что ответило).
- Геокодирование по названию города не делается: координаты берутся из `.env`.
