# 🌤 weather-bot — сводка погоды и моря из нескольких источников

Телеграм-бот, который собирает погоду и состояние моря для точки прогноза
(по умолчанию Адлер, Сочи) **параллельно с нескольких независимых площадок**,
приводит их к единым моделям, считает обобщение (медиана, разброс, мода,
круговое среднее), определяет опасные события и присылает сводку и
оповещения в Telegram — в виде красиво оформленных **Rich-сообщений**.

```
Адлер — обобщённая сводка погоды и моря
Обновлено: 30 сентября 2026, 12:38 (МСК). Точка: 43.427292, 39.917107
Источники: Open-Meteo, OpenWeatherMap, wttr.in, Open-Meteo Marine, USGS (5 из 5)

Сейчас: +19 °C, ощущается как +19 °C, небольшой ливень.
Влажность 92%; ветер 20 км/ч (ЮВ, 129°); порывы до 26 км/ч.

Море: вода +23 °C, волна 0.6 м.

События (ближайшие сверху):
— сегодня, 30 сентября:
  ⚠️ Дождь · 13:00–16:00 — до 3.2 мм/ч, вероятность 93%
  ⚠️ Гроза · 16:00–17:00 — порывы до 55 км/ч, CAPE до 160 Дж/кг
```

## Возможности

- **Мультиисточниковость.** Погода — Open-Meteo, OpenWeatherMap, wttr.in;
  море — Open-Meteo Marine; землетрясения — USGS. Площадки опрашиваются
  параллельно, упавшая площадка не ломает сводку.
- **Обобщение данных.** По каждому полю — медиана и разброс (min…max),
  описание погоды — мода, направления ветра и волны — круговое среднее
  (корректно через 360°), почасовой консенсус на 48 часов.
- **Детектор опасных событий.** Дождь, ливень, гроза, град, шквал, ураганный
  ветер, риск смерчей, туман, жара, заморозки, резкое похолодание, сильное
  волнение, шторм на море, свежие землетрясения и риск цунами.
- **Рассылка внутри бота.** Ежедневная утренняя сводка в заданное время
  (по умолчанию 07:30 по времени точки) и оповещения за 60 минут до события.
  Дедупликация через JSON-состояние — перезапуск не даёт повторов.
- **Rich-сообщения** (`sendRichMessage`) с заголовками, жирными подписями и
  списками, плюс автоматический откат на обычный текст для старых клиентов.
- **Меню команд** (`setMyCommands`) — кнопка «Меню» рядом с полем ввода.
- **CLI без Telegram** — ту же сводку можно напечатать/сохранить из консоли.
- **Офлайн-тесты** на фикстурах ответов площадок (сеть не нужна).

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/start` | приветствие и инлайн-кнопки |
| `/weather` | погода сейчас и прогноз по дням |
| `/sea` | море: вода, волна, зыбь и прогноз волнения |
| `/events` | что опасного ждёт в ближайшие часы |
| `/full` | полная сводка с событиями, разбором площадок и расхождений |
| `/subscribe` | подписка на утреннюю сводку и оповещения |
| `/unsubscribe` | отключить рассылку |
| `/status` | состояние рассылки, подписки и файла состояния |
| `/whoami` | показывает `chat_id` (для белого списка) |
| `/help` | справка |

## Стек

- **Python 3.10+**, `asyncio`, `dataclass(slots=True)`, type hints
- **aiogram 3** — long polling, Router, инлайн-кнопки, Rich-сообщения
- **httpx** — асинхронные HTTP-запросы (один общий `AsyncClient` на сбор)
- **python-dotenv** — конфигурация из `.env`
- **pytest + pytest-asyncio** — 80 офлайн-тестов на фикстурах
- **systemd** — развёртывание, автоперезапуск, блокировка от второго экземпляра

Внешних фреймворков (FastAPI/SQLAlchemy/ORM) нет намеренно: проект лёгкий,
состояние — JSON-файл, зависимостей всего 3 + 2 тестовых.

## Архитектура

```
weather-bot/
├── app/
│   ├── config.py         # Settings из .env (точка, ключи, пороги, режим отладки)
│   ├── models.py         # нормализованные модели: Current/Day/Hourly/Marine/Quake/Report
│   ├── codes.py          # коды WMO: нормализация и предикаты (дождь/снег/гроза/град/туман)
│   ├── timeutil.py       # часовые пояса и локальное время точки
│   ├── wmo.py / wwo.py   # числовые коды WMO и WWO -> русские описания
│   ├── sources/          # адаптеры площадок + параллельный сбор
│   │   ├── base.py       # базовый класс площадки и помощники разбора
│   │   ├── open_meteo.py / openweathermap.py / wttr_in.py
│   │   ├── open_meteo_marine.py
│   │   ├── usgs.py       # землетрясения (FDSN, ключ не нужен)
│   │   └── __init__.py   # реестр площадок и asyncio.gather
│   ├── aggregate.py      # медиана, разброс, мода, круговое среднее, консенсус
│   ├── events.py         # детектор опасных событий (пороги из настроек)
│   ├── formatting.py     # текст сводки (разделы включаются выборочно)
│   ├── rich.py           # текст -> HTML Rich Message + отправка с откатом
│   ├── service.py        # сбор сводки + кэш на 5 минут
│   ├── subscribers.py    # состояние бота: подписки и отправленное (JSON)
│   ├── notify.py         # рассылка: утренняя сводка и оповещения
│   ├── lockfile.py       # блокировка state/bot.lock (второй экземпляр нельзя)
│   └── bot.py            # aiogram 3: команды, кнопки, меню, фоновый цикл
├── tests/                # pytest: фикстуры ответов площадок + тесты (80 шт.)
├── run_bot.py            # точка входа: бот, --check, --events, --notify-dry, --notify-test
├── weather_report.py     # CLI: печать/запись сводки без телеграма
├── hello.txt             # пример сводки, созданный CLI
└── .env.example          # шаблон конфигурации
```

**Поток данных:** `service.fetch_report()` → `sources.collect_all()` (параллельный
`asyncio.gather`) → `aggregate.build_report()` (обобщение) → `events.detect_events()`
(события) → `formatting.format_report()` (текст) → `rich.text_to_rich_html()`
(оформление) → `bot.send_rich_message()` с откатом на текст.

## Установка

```bash
git clone <repo-url> weather-bot && cd weather-bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # заполните TELEGRAM_BOT_TOKEN и, при желании, OPENWEATHER_API_KEY
```

Требуется Python 3.10+. Токен бота — от [@BotFather](https://t.me/BotFather).
Ключ [OpenWeatherMap](https://home.openweathermap.org/api_keys) опционален:
без него площадка пропускается, сводка работает на остальных.

## Запуск

```bash
# Telegram-бот (long polling + рассылка)
python3 run_bot.py

# Проверки без Telegram
python3 run_bot.py --check                    # проверить токен методом getMe и выйти
python3 run_bot.py --events                   # события ближайших часов в консоль
python3 run_bot.py --notify-dry               # прогон рассылки без отправки
python3 run_bot.py --notify-test              # проверочное сообщение подписчикам

# CLI-сводка (телеграм не нужен)
python3 weather_report.py                     # сводка в терминал
python3 weather_report.py --sea-only          # только море
python3 weather_report.py --out hello.txt     # записать в файл
python3 weather_report.py --json report.json  # плюс машинночитаемый JSON
python3 weather_report.py --sections current,events,forecast --days 1

# Тесты (сеть не используется)
python3 -m pytest
```

## Площадки

| Площадка | Что даёт | Ключ |
| --- | --- | --- |
| Open-Meteo | текущая погода, прогноз по суткам, УФ-индекс, рассвет/закат | не нужен |
| OpenWeatherMap | текущая и прогноз 3-часовыми шагами | нужен |
| wttr.in | текущая погода, 3 суток, вероятность дождя | не нужен |
| Open-Meteo Marine | температура воды, высота и период волны, зыбь | не нужен |
| USGS | землетрясения в радиусе точки (FDSN, GeoJSON) | не нужен |

## Как считается обобщение

- по каждому числовому полю — **медиана** среди площадок; отдельно считаются
  минимум и максимум, из них собирается строка «Разброс по источникам»;
- описание погоды — **самое частое** среди площадок, плюс перечисление, кто что сообщил;
- направления ветра и волны — **круговое среднее** (корректно через 360°);
- если разброс температур ≥ 3 °C, в конце сводки появляется предупреждение;
- упавшая площадка не ломает сводку: её текст ошибки уходит в «Примечания».

## Рассылка и оповещения

Рассылка живёт внутри процесса бота (`app/notify.py`) и раз в
`NOTIFY_POLL_SECONDS` проверяет расписание:

- **Утренняя сводка** — раз в сутки в `NOTIFY_DAILY_TIME`. Если бот лежал в момент
  отправки, сводка уйдёт при первом запуске в пределах `NOTIFY_DAILY_GRACE_MINUTES`.
- **Оповещения о событиях** — за `NOTIFY_EVENT_LEAD_MINUTES` до начала, в пределах
  `NOTIFY_EVENT_HORIZON_HOURS` вперёд. Ключ события — тип и час начала
  (`rain:2026093008`), поэтому дублей при перезапуске нет.
- Подписки и отправленное — в JSON-файле `STATE_FILE`, история чистится через 7 дней.

## Развёртывание под systemd

```ini
[Service]
Type=simple
User=botuser
Group=botuser
WorkingDirectory=/home/botuser/bots/weather-bot
EnvironmentFile=/home/botuser/bots/weather-bot/.env
Environment=PYTHONUNBUFFERED=1
ExecStart=/home/botuser/bots/weather-bot/.venv/bin/python /home/botuser/bots/weather-bot/run_bot.py
Restart=on-failure
RestartSec=10
StandardOutput=journal
StandardError=journal
```

```bash
sudo systemctl enable --now weather-bot.service
systemctl status weather-bot.service
journalctl -u weather-bot.service -f
sudo systemctl restart weather-bot.service   # после обновления кода
```

Второй экземпляр бота запускать нельзя: Telegram отдаёт обновления только одному
получателю (иначе 409 Conflict). Поэтому `main()` берёт блокировку `state/bot.lock`
и при занятом файле завершается с сообщением «Бот уже запущен (pid …)».

Тесты офлайн, на фикстурах в `tests/fixtures/`. Покрыты обобщение, детектор

## Ограничения

- Фикстуры `openweathermap_*.json` синтетические (реального ответа без ключа нет),
  собраны строго по схеме документации — см. поле `"_note"` внутри файлов.
- wttr.in не отдаёт русские описания даже при `lang=ru`, поэтому они переводятся
  по числовому коду WWO (`app/wwo.py`) с резервным переводом английских фраз.
- Площадки используют разные модели и время наблюдения — числа расходятся, это
  нормально и показывается в сводке явно.
- Детектор событий работает по консенсусу площадок: чем больше площадок отвалилось,
  тем меньше уверенность в событиях.
- Оповещения о землетрясениях — не официальное предупреждение, а напоминание
  проверить сводки USGS/МЧС; риск цунами оценивается грубо.
- Геокодирование по названию города не делается: координаты берутся из `.env`.
